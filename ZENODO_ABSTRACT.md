# Abstract

**proofrecord-aar-interop v0.1.0-rc.5: signed ProofRecord™ and Agent Action Receipts (AAR) interoperability demonstration**

Creator: Derek Hone, Remnant Fieldworks Inc.

Autonomous agents increasingly need two separate kinds of evidence: proof that an action was authorized before it executed, and a receipt of what was actually dispatched. This package demonstrates, with synthetic data only, how an Ed25519-signed ExecutionProof ProofRecord™ can be cited by an Agent Action Receipts (AAR) v0.2 bundle through AAR's existing `decision.evaluated_inputs` field, without any change to the AAR schema, and how a relying party can check offline that the dispatched action equals the authorized one: action name, target, exact parameter bytes, actor credential, validity window and single use.

The package contains a signed synthetic ProofRecord, its public test key, a citing AAR bundle generated by AAR's own harness, an offline verifier using the Python standard library plus PyNaCl (libsodium) for Ed25519 (the sole signature-acceptance gate), positive and negative fixtures, and 97 targeted tests. The verifier reports ProofRecord validity, cross-record consistency, AAR reference-verifier conformance and outcome evidence as separate levels; no level implies another.

The package also makes reproducible an observation: in this fixture set, 16 of 21 harness-generated AAR bundles are conformant under AAR's reference verifier while disagreeing with, failing to cite, or ambiguously citing the ProofRecord. Because AAR treats `evaluated_inputs` as opaque, this is not claimed as an AAR defect; it shows that AAR conformance alone says nothing about ProofRecord agreement.

**Limitations.** All results are same-author and are not independent validation. This is not formal AAR conformance and is not endorsed by AAR. The key is a synthetic test key. Signing-key misuse (T18) is not prevented; cross-bundle replay is not tested; outcome evidence is not independent.

Keywords: ExecutionProof; ProofRecord; Agent Action Receipts; pre-execution authorization; Ed25519; interoperability; offline verification; AI agent accountability.
