# EP-PR-1 ProofRecord signature specification (demonstration profile)

Normative implementation: `epverify/proofrecord.py`. Sole signature-acceptance gate: `epverify/ed25519_verify.py`.

| # | Item | Definition |
|---|---|---|
| 1 | Algorithm | Ed25519 (RFC 8032, pure, no prehash, no context). Signed with pyca/cryptography (OpenSSL). Verified with libsodium (via PyNaCl 1.6.2) plus stricter pre-checks (item 7). This is the only acceptance path; a more permissive Ed25519 implementation (for example one that accepts small-order keys) must not be used to accept a ProofRecord. **No novel primitive.** |
| 2 | Signature input | `"EP-PROOFRECORD-v1"` (17 ASCII bytes) ‖ `0x00` ‖ `RF-CJ-1(body)` |
| 3 | Canonicalization | RF-CJ-1. UTF-8 JSON. Object keys match `[a-z][a-z0-9_]{0,63}`, sorted by code point, no duplicates. No whitespace. Integers only (\|n\| ≤ 2^53−1, no `-0`, no leading zeros). No floats, no `null`. Strings must be NFC and minimally escaped. Max 65,536 bytes, depth ≤ 16. **The whole file must equal `RF-CJ-1(envelope)` byte for byte**, else `NON_CANONICAL`. Serializers accept exact built-in types only (subclasses rejected). Action parameters are additionally encoded as RFC 8949 §4.2.1 deterministic CBOR for `parameters_digest`, the same bytes AAR hashes. |
| 4 | Covered fields | The entire `body` object, closed set: `v, alg, kid, proofrecord_id, authorization_id, decision, actor{actor_id, identity_basis, token_issuer, token_subject, aar_subject_credential_id}, action{action_name, target_id, parameters, parameters_encoding, parameters_digest}, enforcement_point_id, policy{policy_id, policy_version}, issuer, issued_at, not_before, expires_at, nonce, use, key_notice`. An extra or missing member is `INVALID/SCHEMA`. |
| 5 | Excluded fields | Only `sig` (envelope). The relying party supplies the public key file and the evaluation time; neither is covered by the signature. Implications: (a) trust comes **only** from the relying party pinning the key, and the in-record `kid` is a selector, not a trust anchor; (b) `--at` is caller-supplied, so a wrong clock gives a wrong validity answer; (c) **the AAR citation is outside this signature.** It is signed by AAR's issuer key and checked by AAR pyref. |
| 6 | Signature encoding | `sig`: 128 lowercase hex characters = R(32) ‖ S(32) per RFC 8032. Uppercase or other lengths: `INVALID/SIG_FORMAT`. |
| 7 | Public key | Key file (RF-CJ-1): `{alg:"Ed25519", kid, public_key_hex (64 lowercase hex, RFC 8032 encoding), notice}`. Rejected: y ≥ p (non-canonical), points that do not decode, small-order points (8·A = identity), S ≥ L. Verification is cofactorless (`[S]B = R + [k]A`). |
| 8 | Key id and trust | `kid = hex(SHA-256("EP-PROOFRECORD-KID-v1" ‖ 0x00 ‖ public_key))`. The key file's kid must match its key (`KEYFILE_KID_MISMATCH`). `body.kid` must equal the pinned kid (`KID_UNKNOWN`). There is no key discovery, no certificate chain and no revocation. **Trust is out-of-band pinning.** |
| 9 | Domain separation | Signature domain `EP-PROOFRECORD-v1\0`. Key-id domain `EP-PROOFRECORD-KID-v1\0`. AAR citation name `executionproof.proofrecord.v1`. ProofRecord reference = SHA-256 of the exact file bytes. |
| 10 | Versioning / downgrade | `v` must be `ep-proofrecord/1` and `alg` must be `Ed25519`. Both are checked before the signature and are also signed. Any other value is `UNSUPPORTED` (exit 3). No negotiation, no fallback, no `none`. |
| 11 | Tampering | Any change to covered bytes gives `SIG_INVALID`. A re-serialized file (whitespace, key order, escapes) gives `NON_CANONICAL`. Duplicate keys, floats, null, lone surrogates and truncation give `PARSE`. A signed but internally inconsistent record gives `SCHEMA`, `PARAMS_DIGEST_MISMATCH`, `ACTOR_SUBJECT_MISMATCH` or `TIME_INCOHERENT`. |
| 12 | Failure semantics | Fail closed. Check order: parse → canonical → envelope → version → alg → sig format → kid → Ed25519 → body schema → parameter digest → time coherence. The first failure is reported and nothing after it is evaluated. Only `VALID` + `ALLOW` + (if `--at`) inside `[not_before, expires_at)` is reported as authorization. HOLD/DENY give `NOT_AUTHORIZED` (exit 4). |

Body rules: `actor_id == "agent:" + token_subject`. `issued_at ≤ not_before < expires_at`. `expires_at − not_before ≤ 300` s. `use == "single"`. Parameter values may be str, int or bool, and the map must be non-empty. `key_notice == "SYNTHETIC-DEMONSTRATION-KEY-NOT-PRODUCTION"`.

This is a demonstration format. It is not JWS or COSE. A COSE_Sign1 profile aligned with AAR's wire format is a possible follow-on and is **not** implemented here.
